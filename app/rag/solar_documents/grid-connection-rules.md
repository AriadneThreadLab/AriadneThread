# Grid-connection rules for photovoltaic plants

Utility-scale and many commercial photovoltaic plants interact with
transmission or distribution codes. This note summarises the kinds of rules
that appear in European network-code practice. It is not a site-specific
interconnection study and not a substitute for SolarDSS grid-distance layers.

## What grid rules typically cover

Network codes describe connection requirements, reactive-power behaviour, fault
ride-through expectations, and notification processes for new generating
units. Distribution operators may add plant-level protection, metering, and
export-limitation conditions. These documents define obligations. They do not
measure how far a candidate is from a feeder. Distance and hosting-capacity
figures belong to analytical engines and utility studies.

## How rules can affect a site conceptually

A site may be affected because the project intends to export power, because it
exceeds a size class that triggers a different code, or because the local
network requires studies before an offer is issued. Explaining that a
jurisdiction applies a requirements-for-generators type of code is knowledge
evidence. Stating that this parcel fails a maximum-grid-distance screen is
analytical evidence from SolarDSS or from a utility.

## Grounding answers about regulation of the grid interface

When a user asks what regulation affects a site, name the class of grid code
and the need to check the local operator, then cite this document. Do not
invent an available transfer capacity or a feeder rating. If SolarDSS returned
a grid-connection slot or a distance indicator, report that value in the
deterministic partition and keep this note in the document partition.
